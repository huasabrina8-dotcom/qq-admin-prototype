一、需求背景与目标

Juan365 前台需求已分散在多个原型仓库，运营日常用的是同一套后台。要把登录、会员、充提、资金、游戏、优惠做成可点原型，让开发测试按同一路径验收。

路径

一级菜单（截图锁定原文）：会员管理、更多记录、充值提款、资金操作、平台游戏、优惠活动、报表管理。点 Logo JUAN 进仪表盘。会员管理 11 项：会员中心、会员分组、会员账单、KYC审核管理、自我限制、短信查询、登录日志、用户行为日志、提款账户管理、会员ID查询、用户分层。

UAT getInfo（2026-08-16）校正：截图「更多记录」= 线上「投注记录」。超管另可见任务系统、联盟管理、综合报告、渠道管理、信息配置、平台配置、负责任博彩、投注站、风控、盈亏异常、地推、系统设置。各页列名见 Markdown 2.21（UAT 源码）。搜索五项 / 列表三项的完整逻辑见 2.22。

权限

原型无需登录，打开即超管后台。下表为正式环境角色规格。

业务要求（Locked）

  • 禁止跨币种汇总；一键回收只收当前币种子平台。
  • 充值通过才加款；提款通过先扣可用、加冻结；流水不达标不得通过。
  • 人工调账原因必填。抽奖深配置以抽奖项目为准。QRPH 审核通过不在本原型自动发返利。

四、异常场景

接口失败可重试；空数据「暂无数据」；原型无未登录跳转（正式环境仍跳登录）；无权限拦截；重复审核行操作变 —；余额不足/流水不达标不改单；会员不存在引导返回。完整表见 Markdown 第四节。

五、验收标准

  • 功能：打开即进后台（无需登录）；七菜单、会员详情 Locked 示例、充提与划转流水。正式角色权限见 Markdown。
  • 页面 / 交互：中文、页签、确认取消不改数、资金 Toast 带「演示，不产生真实资金」。
  • 数据：两位小数、不跨币种加总、重置恢复 seed。
  • 异常 / 兼容 / 性能：按 Markdown 第五节勾选。
  • 埋点：本项目不要求。
